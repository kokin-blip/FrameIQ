# Milestones 1–4: implementation and remaining gates

Updated 2026-10-09. This is a working implementation, **not a declaration that all four milestones are release-ready**. The Fluent docked editor, original projects, offline extraction, and FrameRefV1 remain intact. Migration 001 is unchanged.

## Implemented

- R1: numbered, checksummed migrations 002–007; SQLite backup API before upgrades (including live WAL data), foreign-key checks and upgrade fixtures. Existing contracts still deserialize additive fields.
- R4: cancellable SHA-256 relocation; identical content preserves indexes/selections/analysis; different content is rejected; missing-file actions in Library/Studio. “Import replacement” deliberately creates a separate imported source instead of silently changing source identity.
- R5: immutable persisted export plans, per-image/sidecar checksums, restart recovery, new attempts, resume/dismiss UI, collision protection and source verification. Recovery regenerates missing owned outputs and never overwrites a changed file. Tests reopen the application between export and resume. Explicit fault-injection tests now terminate the application at five boundaries: before/after ownership checkpoint, after image, after sidecar, and after item checkpoint. Reopening and repeated resume verify outputs, immutable selections and preservation of unrelated files. Verified skips now emit FRAME_SKIPPED instead of falsely reporting FRAME_EXPORTED; per-attempt persisted skip totals remain to be added. Fault hooks are absent from normal release builds. App-owned export staging now lives in the application cache and is cleared under the single-instance lock on restart; all five crash points verify cleanup. Older destination-local temporary directories are not deleted automatically because their ownership cannot be proven.
- R6: decoded-frame color conversion with zimg/zscale and Hable tonemapping; tagged sRGB output and PNG16 with cICP, mDCV/cLLI when present. Sidecars record the actual transform, peak source/fallback, interpretation, and HLG reference behavior. PQ/HLG fixtures validate RGB16 and tagged SDR exports. Unknown metadata requires an explicit source interpretation. Dolby Vision dynamic metadata is excluded. Independent analytical ramps and additional real HDR fixtures are still required.
- A1/A2: complete-timeline capped coarse sampling, refinement, final indexed-frame neighborhoods, reusable versioned metrics, sharpness/blur/exposure clipping/luminance percentiles, pHash + SSIM duplicate suppression and cached weighted ranking. Ordered batch passes avoid per-frame processes. Current implementation still decodes a sequential codec pass for each sampling phase; shared-keyframe batch seeks remain an optimization task.
- A3: Analysis dock, explanations, partial/cancelled results, exact frame restoration, existing collection integration, 2–4 frame comparison, fit/actual-pixel modes, linked zoom/pan and metadata/metric labels. Packaged macOS analysis/comparison smoke-tested; full minimum-size and failure-state visual review is unfinished.
- M1/M2: bounded persistent AI worker, session reuse, CPU reference execution, supervision/timeouts/cancellation, native memory sampling, a 25%/4 GiB managed budget, low-memory reserve and benchmark persistence. Download/local-runtime operations are supervised too, so cancellation kills the app-owned worker without terminating Ollama/LM Studio. Native media/inference requests now share a cancellable CPU-slot budget (half the logical cores, capped at four); pending interactive decode is admitted before background work, and managed decoder/filter/ORT sessions use one compute thread per slot. Network waits do not consume CPU slots. Hashing/ranking/image metrics outside native workers and accelerated-provider fallbacks still need broader resource profiling.
- M3: reviewed manifest UI; resumable strong-ETag downloads, SHA-256 and graph validation, staged ONNX imports, atomic installation, model removal, dependent worker shutdown. Supported import templates: one bounded NCHW or explicitly declared NHWC float32 input and named bounded float32 outputs using allowed standard operators. External weights/custom executable operators/subgraphs are rejected. Download retry discards corrupted retained files. Channel order, layout and normalization have numeric unit coverage. ROI task templates, lifecycle fault injection and download-cache cleanup require further work. Import cancellation is checked before activation, and a database failure removes the new owned installation.
- M6: opt-in loopback-only Ollama/LM Studio discovery, image capability checks and synthetic-pixel probes; remote/cloud-marked Ollama models and text-only models are ineligible. Optional credentials use OS credential storage. Runtime network responses are bounded, redirects/proxies disabled, and cancellation is exposed through Activity. Real server interoperability and both-platform credential-store tests remain pending.
- M4 face foundation: a YuNet decoder now provides boxes, five landmarks, clipped-area fraction and landmark-in-frame flags in source-normalized coordinates. Aspect-preserving 640-pixel preprocessing, integer-box NMS, output bounds/finite validation and padding rejection have unit coverage. Indexed face jobs, migration 005 caches and model-dependent cleanup are implemented and tested with a deterministic IPC double. Detection scores are not visibility probabilities or face identity. OpenCV numerical parity tools and a provenance-tracked public-domain NASA image are added; square, padded landscape, padded portrait and two-face ONNX/OpenCV tensor/box/landmark parity all pass after memory recovered; these transformed examples are correlated parity fixtures, not an accuracy dataset. Automatic presets remain disabled pending held-out visibility evaluation and the remaining person/pose capabilities.
- M4 person/pose continuation: reviewed FP32 manifests pin official model names, tensor layouts, weights and directory-specific Apache-2.0 license links. Person preprocessing uses normalized RGB float32 with neutral centered padding, reference stride anchors/logit decoding and the pinned reference NMS convention. Typed DetectPersons IPC runs in the persistent worker and shares CPU admission. Square/landscape/portrait/two-person numerical reference checks pass; source-coordinate discrepancies remain below 0.001 pixels on these correlated fixtures. Detector regions are deliberately not described as full-body boxes. Pose ROI geometry matches reference crop/pad/rotation transforms; invalid, disjoint and oversized ROIs abstain. Pose raster preprocessing, landmark postprocessing and source-sized binary person masks are now implemented. Worker EstimatePose returns typed landmarks and atomically written/checksummed PNG masks. The decoder passes reference checks on identical tensors across four correlated fixtures; three fixtures also pass the current raw-runtime tensor tolerance, while landscape records a segmentation-logit discrepancy and remains an explicit unresolved parity gate. No automatic preset capability is enabled by this work. The decoder pass introduced no project migration or UI redesign. Indexed caching is added in the continuation below.
- P foundations: seven immutable built-in definitions with approved initial weights; normalized custom versions; guided per-frame rectangles and independent region metrics, deletion/correction through redraw, persisted provenance. Automatic capabilities are explicitly unavailable. Guided measurements do not masquerade as automatic visibility or apply a region across unrelated frames.
- R2: synthetic decoder/HDR fixtures, backend benchmark executable and a permissioned-corpus annotation specification. No unlicensed or private imagery committed.
- R3: pinned MSVC/vcpkg FFmpeg overlay builder, restricted LGPL options, zimg, DLL dependency audit, verified ORT runtime lock, NSIS packaging and Windows native CI job. **Prepared but not executed on Windows.**

## What is not implemented or validated yet

1. M4: resolve landscape segmentation-logit runtime parity, face visibility calibration and held-out evaluation. Person detection and pose ROI coordinate geometry now have numerical reference checks; indexed detector-to-pose jobs now run, but their numerical checks are not held-out accuracy validation. YuNet geometry/landmark adapter and indexed cache jobs are implemented; broader reference parity and held-out accuracy are still required. Generic tensor compatibility and coordinate unit tests are not a visibility release gate.
2. M5: HairSegmenter conversion/rights/parity/IoU decision and bounded GroundingDINO accessory/footwear feasibility. No pack is silently substituted or enabled.
3. P1/P2: shot-scoped tracking and corrections, visibility/size eligibility, region-aware full-video rankings, view-orientation confidence and complementary Complete Look selection. Current guided regions are frame-specific and untracked. The preset controls save definitions; automatic preset execution stays unavailable.
4. M2/M3: accelerator detection/validated CPU fallback and hardware-based quality recommendations, resource profiling beyond native worker slots, ROI import templates, model-upgrade/download crash matrix and dependent-cache lifecycle tests.
5. R3/R7/V1: Windows CI execution, clean Windows 11 installation/worker tests, both-platform memory profiling, broad real-video corpus and 30 permissioned clips/300 annotated frames. Synthetic fixtures cannot establish 80% recommendation acceptance, 95% duplicate precision, 90% visibility precision, or hair IoU.
6. A3/P3/V1: finish 1440×960 and 1000×700 native visual review, long filename/focus/error/cancellation checks, screenshot comparison against Figma and all preserved workflows on packaged builds. macOS locked intermittently during review; Windows is unavailable in this environment.

These are explicit follow-up tasks, not implied successes. In particular, **milestone 3 is a guided-region/configuration foundation rather than completed automatic intelligent presets**.

Inspect generated configuration/licenses and install the NSIS artifact on a clean Windows 11 machine. Models: open models/manifests/yunet-2023mar.json from Settings, inspect the pinned provenance/license/checksum, then download or import the matching ONNX file. It appears as compatibility-checked, not accuracy-validated. No model weights are bundled with the app.
